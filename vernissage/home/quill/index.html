quill.

A relational database written from scratch in Go: a B+tree on slotted pages, a SQL parser and planner, a write-ahead log, and the PostgreSQL wire protocol, so the real psql connects to it.

Connect

Any user name works and there is no password.

psql -h quill.example -p 15433 -U quill

Try these

The database is a small shop (users, products, orders) and 3,000 sensor readings.

SELECT u.name, COUNT(*) AS orders, SUM(o.total) AS spent
  FROM users u JOIN orders o ON u.id = o.user_id
 GROUP BY u.name HAVING SUM(o.total) > 150
 ORDER BY spent DESC;
SELECT COUNT(*), AVG(value), MIN(value), MAX(value)
  FROM readings WHERE sensor = 7;

Ask for the plan. Looking up a primary key walks the B+tree, which is three page reads however big the table gets:

EXPLAIN SELECT * FROM readings WHERE id = 42;

Filtering on any other column reads the whole table. The planner makes one decision, on the primary key, and does not choose secondary indexes yet; the README lists that as the next piece of work.

EXPLAIN SELECT * FROM readings WHERE sensor = 42;

What this instance allows

  • Read only: every INSERT, UPDATE, DELETE and CREATE is refused, so everyone sees the same data.
  • A statement that runs longer than 3 seconds is cancelled, and a query returning more than 1,000 rows is refused. Statements run one at a time, so one slow query would otherwise make everyone wait.
  • To change data, run quill yourself: it is one static binary and one file.
